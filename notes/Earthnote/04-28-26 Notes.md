
## Build (in phase13_pilot.py:306 stack_hourly_utc)

  - Inputs: the 30min tensor (~31×192 = ~5950 segments) with each segment's times_hours (midpoint, hours since DOY-1 00:00 UTC)
  and the set of valid DOYs.
  - Bucketing: hour_bucket = floor(times_hours) — assigns each 30-min segment to the integer UTC hour containing its midpoint.
  So one hourly bucket sweeps midpoints in [h, h+1).
  - Stack within bucket: plain np.mean(cc_arr[m], axis=0) — linear mean, not median.
  - Membership: any 30-min segment whose midpoint lands in hour h is included. Because CC_LEN=1800 s, CC_STEP=450 s, segments
  are spaced 7.5 min apart → ~8 segment midpoints per hour, but each segment overlaps neighbors by 75% in time. The bucket
  itself is 1 hour wide on midpoints, so neighboring hourly stacks share zero segments by construction.
  - Output: hourly.npy shape (n_hours, 4801) and hourly_times.npy (float hours since DOY-1 00:00 UTC). For Jan 2020 you get up
  to 31×24 = 744 hours; in practice fewer due to data gaps.
  - The "non-overlapping hourly buckets" claim in phase2.md is correct on the bucket boundaries (no segment midpoint is in two
  buckets) but the underlying segments still overlap within a bucket.

## dv/v measurement on the hourly stack

  - Filter: _measurement_bandpass (Butterworth order-4, 2–4 Hz, zero-phase) applied to hourly → hourly_m before any measurement.
  - Stretching: stretching_dvv(hourly_m, ref_m, lags, side, use_abs=True, cc_qc=0.0) for each side ∈ {pos, neg, both}. ε=±5%,
  2001 grid points, |corrcoef| peak picking. Saved as dvv_stretch_hourly_{side}.npy and cc_stretch_hourly_{side}.npy (signed cc
  at peak).
  - MWCS: mwcs_dvv(hourly_m, ref_m, lags, side, fs=40). 4 s sub-windows / 2 s step, phase fit in 2–4 Hz. Saved as
  dvv_mwcs_hourly_{side}.npy and cc_mwcs_hourly_{side}.npy (formal Δt error, not coherence).
  - QC variant (stretching only, hourly only): dvv_qc = where(|cc| >= 0.5, dvv, NaN) → dvv_stretch_hourly_{side}_qc.npy. This is
   what drives the headline "hr-QC std" metric in the Tier ranking.
  - Reference for both methods: monthly linear mean of all 30-min CCs (ref.npy), bandpassed to 2–4 Hz at measurement time.

## How the hourly series is shown

  - (2,0) panel: hourly stretching dv/v, 3 sides on one axis, with a 24-h running median overlay computed at plot time only.
  Time axis is hourly_times / 24 (DOY-relative).
  - (2,1) panel: hourly MWCS dv/v, same layout, error bars from formal σ_Δt.
  - (3,0) panel: |corrcoef| histogram across all hourly samples (3 sides overlaid) — this is where you'd see grid-clipping if it
   returned.
  - The Clements-style |cc|-weighted pos+neg combine is computed inline in phase13_replot.py for the hourly panel only and not
  persisted.

  So for phase2p1.py planning, the levers on the hourly side are:
  1. The bucket stack is a linear mean over ~8 overlapping segments — switching to per-lag median (like the daily) is a one-line
   change and probably reduces glitch sensitivity on noisy hours.
  2. ε grid width and MWCS sub-window length (the items I flagged earlier) — both act on the same hourly_m tensor.
  3. QC threshold is fixed at 0.5; could be made adaptive to per-station SNR, or replaced with a coherence threshold on MWCS as
  well.
  4. Reference is monthly linear mean — could try monthly median, or a per-hour reference (stack only the hour-of-day's hourly
  stacks together) to remove diurnal source-spectrum bias.
