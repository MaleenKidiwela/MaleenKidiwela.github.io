## GAIA meeting notes

### **1. Agentic Architecture, LLM Evolution & Economics**

- **Agent Definition & Architecture:** An AI agent is not merely an isolated LLM, but a full infrastructure that pairs an LLM with external tools (such as GitHub issues and pull requests) through protocols like Model Context Protocol (MCP). Agents operate token-to-token, executing actions using file permissions and tool access.
- **Model Behaviors & Culture:**
    - Different LLMs handle "thinking" steps differently; Claude tends to be more verbose by explicitly streaming intermediate reasoning steps, whereas OpenAI models tend to perform reasoning in the background before outputting final results.
    - **Marine** notes that OpenAI operates as an opaque culture and model, while Anthropic models are characteristically "boozy" in their detailed outputs.
- **Token Economics & Usage Budgets:** Because output tokens incur costs, providers intentionally manage output limits. A complete token budget incorporates the system prompt, user inputs, PDF papers, codebase context, tool/skill definitions, text output, and generated visual artifacts (like PNG plots). Researchers should adopt a cost-efficiency mindset for token usage similar to managing compute in geophysical processing.
- **Historical Timeline of Capabilities:**
    - **Nov 2022:** Initial text-based chatboxes appear.
    - **2023:** Introduction of tool attachments to make LLMs actionable.
    - **Nov 2024:** Introduction of MCP to standardize tool connections.
    - **Early 2025:** Emergence of specialized coding agents.
    - **2026:** Expansion to 1M+ token context windows, enabling entire codebases, 10+ research papers, or a 2-hour movie (e.g., Kimi) as direct input context.
- **Geoscience Adoption Gap:** Geosciences lag behind fields like biology, drug discovery, robotics, and astrophysics because geoscientific problems are inherently more unknown and complex.
- **Modern Guardrails:** Contemporary agent workflows benefit from lower hallucination rates, retrieval grounding (such as automated DOI verification), structured system prompts, and automated test writing ("bread and butter").

### **2. Git Integration & Research Accountability**

- **Abstracting Git Overhead:** **Vikram** points out that for beginner or intermediate Git users who struggle with complex branching and merging, agentic tools eliminate technical overhead by allowing users to execute Git actions using natural language prompts.
- **Audit Trail & Reproducibility:** Marine and Maleen emphasize that non-linear research workflows benefit significantly from Git commit histories and GitHub issue tracking. This structure creates an auditable trail of evidence, making research accountable and allowing researchers to reconstruct complete workflows or roll back decisions if a research direction proves wrong.

### **3. Human-in-the-Loop, Verification & The "Grad Student" Paradigm**

- **Detecting Subtle Visual/Spatial Errors:** A participant shares an experience where an AI tool created a map placing Minneapolis in Wisconsin during a college search with her son. This highlights a core challenge: code often runs without raising runtime errors while producing subtly incorrect spatial or visual outputs.
- **Data Quality Control (QC):** **Marine** identifies human oversight as the primary bottleneck and requires agents to plot raw waveforms to visually inspect and confirm that underlying datasets actually exist.
- **The "Graduate Student" Supervision Paradigm:**
    - **Vikram** compares managing an AI agent directly to supervising a graduate student, where researchers build confidence incrementally by reviewing intermediate outputs.
    - To balance zero-shot over-reliance, **Vikram** recommends breaking complex tasks into explicit steps: plotting a single waveform first, validating data formats, and requiring the agent to output reusable Python scripts or Jupyter Notebooks for step-by-step debugging.
    - Referring to a faculty mailing list discussion regarding OpenAI’s Navier-Stokes results, **Vikram** notes that delegating tasks to AI is another form of outsourcing—models are capable, but human direction remains essential. **Marine** adds that unreadable AI-generated proofs or steps diminish scientific utility, making readable intermediate steps critical.
- **Rapid Tool Scaffolding:** **Vikram** notes that agents make it fast and inexpensive to build custom intermediate visualization tools (e.g., custom UI/plotting tools) via simple prompts to streamline manual data inspection.

### **4. Four Modes of Agent Interaction & Real-World Application**

**Marine** outlines four distinct environments for interacting with agents:

1. **Browser Chat:** Web-based chat interfaces (e.g., ChatGPT) suited for simple text queries, family recipes, or light research.
2. **Standalone Apps:** Dedicated applications (e.g., Codex, Claude Code) that send prompts to backend servers while operating directly on local repositories.
3. **IDE Extensions:** Extensions in code editors (e.g., VS Code or Atom) that integrate terminals, chat windows, and notebooks directly within a repository session.
4. **Command Line Interface (CLI):** Executing commands directly in the shell (e.g., `claude -p "prompt"`), enabling remote execution over SSH on Linux servers without a desktop GUI.

- **Project Application (_Quake Scope_):** **Marine** demonstrates using Claude CLI to deploy deep learning models on EarthScope archives. The agent refactored code, managed GitHub issues, created Jupyter notebooks, and built rendered HTML dashboards containing waveform plots.

### **5. Skill Files (`skill.md`), System Prompts & Automation**

- **Definition & Functionality:** Skills are plain-language markdown files (`skill.md`) or system prompts containing explicit rules, rubrics, and instructions for recurring tasks.
- **Programming Function Analogy:** **Vikram** explains that a skill is the agentic equivalent of a function in code: once a manual task becomes repetitive, you write a skill file to automate it.
- **Examples Shared in Presentation:**
    - **Work Log Summarizer:** Maleen demonstrates a skill file that analyzes sequential terminal session logs across a full work day to generate a structured summary detailing chronological timestamps, methods, results, and explicit exclusions.
    - **Seismology Waveform Checker:** Maleen describes a skill created to analyze seismogram figures, inspect P and S wave arrival picks, and automatically flag incorrect picks.

### **6. Model Context Protocol (MCP), Sub-Agents & Workflow Strategy**

- **MCP & Context Overhead:** **Meline** explains that MCP servers outsource tool execution outside the main agent. However, because MCP tool definitions are front-loaded into the context window, heavy MCP tools consume significant token space and can cause the agent to forget critical prior context.
- **Multi-Agent / Sub-Agent Networks:** **Meline** highlights **Marine's** framework for multi-agent research networks, where a primary orchestrator agent delegates tasks to specialized domain sub-agents (e.g., seismologist, hydrologist, geodesist, engineer, statistician). Structuring clear roles and fail-safes upfront prevents token-heavy brute-forcing during execution.
- **Practical Adoption Philosophy:** **Vikram** emphasizes that there is no single "correct" setup and that workflow optimization evolves with experience. He advises researchers to start with simple chat interactions, identify specific friction points, and build custom automations as needs arise.
