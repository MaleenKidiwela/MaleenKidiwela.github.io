# 2026-04-29 — Phase 2.1 adaptive coda window

## Pipeline

30-min CCs (broadband whitened) → 2–4 Hz Butterworth-4 bandpass → **48-h rolling phase-weighted stack** stepped 1 h (each row = PWS of past 48 h, ≥ 80 % of 384 expected segments) → **per-station adaptive coda window** from log-envelope (median, 5th, 95th percentile across all hours; per-row RMS-normalized for shape stability; Hilbert envelope; noise-floor lag from 40–60 s reference) → PWS reference of the rolling-PWS hourly tensor → stretching (±3 %, 6001 grid pts, step 0.001 %) and MWCS (4-s sub-windows / 2-s step, phase fit 2–4 Hz) on each hourly bucket vs the PWS reference. QC mask `|cc| ≥ 0.5`.

Run wall: ~20 min on cascadia (29 stations parallel). `n_hours` per station = 697 max (744 − 48 + 1) for full coverage.

## Adaptive-window criterion

For each station's denoised hourly tensor, compute on the |lag| axis (pos and neg sides separately, then AND):

1. Hilbert envelope, smoothed in lag with 0.5-s box.
2. Per-row normalize by RMS over the candidate range (1.5 ≤ |lag| ≤ 20 s) — removes hour-to-hour amplitude variation from PWS phase weighting; spread then measures shape stability.
3. Compute median m(t), 25th and 75th percentiles across hours.
4. **Spread mask:** `(p75 − p25) / m < 1.0` (IQR / median).
5. **Noise-floor mask:** heavily-smoothed (2 s box) median trend must exceed `2 × noise_level`, where `noise_level` is the median trend over [40, 60] s.
6. AND pos-side and neg-side validity, restrict to [1.5, 20] s, morphologically close gaps shorter than 1 s.
7. Take the **longest contiguous valid run**; require length ≥ 3 s. If none, fall back to the Phase 2 default [2.0, 8.0] s.

Window is symmetric: same `(t_beg, t_end)` magnitude pair applied to both `+lag` and `−lag` coda.

## Notes / next steps

- The criterion fires on ~9 of 29 stations; the rest fall back to [2, 8] s default. That's expected — stations with looser hour-to-hour shape stability don't have a contiguous valid run ≥ 3 s under IQR/m < 1.0.
- Narrowing the coda window below the default gives less averaging and worse hr-QC std even though the criterion thinks it's "removing noise". The narrowed lags still had real signal contributing constructively to stretching cc.
- **Better criterion (proposal):** "default-or-wider" — start from [2, 8] and only **extend** the window if the extension passes the spread + noise-floor test. Never shrink below default. This would keep MDW's gain (window extended to 12.6 s) and avoid the CBS/MANO losses.
- MWCS-NaN on stations with adaptive windows < ~6 s is a feature, not a bug — short lag baseline can't constrain the through-origin phase-slope regression. Leave as is.
- Across-station absolute dv/v amplitudes are not strictly comparable when windows differ (different scattering volumes / sensitivity kernels). Comparison of *temporal patterns* between stations remains valid.
