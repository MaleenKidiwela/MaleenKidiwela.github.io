
## **Meeting Notes: Unified Seismology Workflows & Multi-Sensor Data Integration**

### **1. Core Architectural Strategy & Philosophy**

- **Shared Workflow Scaffolding ("Skeleton")**: The group agreed to establish a standardized, reusable workflow framework across all research projects. While specific model architectures or weights will vary by application, baseline IO handling, data filtering, and core libraries (e.g., SeisBench, ObsPy) must be shared rather than re-implemented.
- **Preventing Code Duplication**: The team strongly cautioned against copying and modifying workflow code across separate repositories. A key example cited was a bug in Richard Weaver’s 2011 error-quantification code (stretching method) that was copied into ObsPy and spread to multiple third-party packages before being identified by Astra. A central shared codebase is required to avoid a "second pandemic of bugs" in observational seismology.
- **Scientifically Grounded Evaluation**: Evaluation of machine learning workflows must move beyond standard AI benchmark metrics (e.g., MAE/MSE) or artificial space/time data splitting. Workflows must be tested on real-world scientific scenarios (e.g., mainshock-aftershock sequences, volcanic swarms, and overlapping events) to ensure validity for global deployments.

### **2. Individual Project Reports & Technical Updates**

#### **A. Alex — Multi-Sensor Integration & Mount Rainier DAS Pipeline**

- **Data Streams & Focus**: Working on phase picking across **Distributed Acoustic Sensing (DAS)** and seismic data, with plans to extend to infrasound, tiltmeters, and hydrophones. Primary target areas are **Mount Rainier** and **Offshore Alaska**.
- **Picker & Association**: Developed a PhaseNet-style picker (`denopic_das`) for GCI data. Avoided intermediate phase association by constraining analysis to known event windows from the 2023–2024 GCI catalog via `libcomcat`.
- **Uncertainty via Inference Dropout**: Instead of multi-model ensembling, Alex applies dropout at inference time (or leverages EQTransformer multi-model outputs) to represent pick predictions as Gaussian distributions, extracting pick timestamps along with uncertainty standard deviations.
- **Magnitude & Data Covariance Weighting**: Calculates local magnitudes using calibrated amplitude-to-magnitude regressions. Developing a **data covariance-based weighting scheme** to integrate heterogeneous, multi-geometry sensor arrays (DAS, short-period nodes, broadband stations) for event location.

#### **B. Orca Volcano (Antarctica) — OBS & Hydrophone Cataloging**

- **Dataset & Setting**: Analyzing a dataset from 15 Ocean Bottom Seismographs (OBS) and hydrophones (OBS + H) deployed for over a year at **Orca (Oka) Volcano** in the Bransfield Basin.
- **Event Context**: Deployed prior to a major regional earthquake swarm (~56,000 events); the OBS array recorded ~3,000 events.
- **Manual Catalog Analyst Drift**: The existing manual catalog suffers from analyst drift (picking consistency changed over time), requiring re-cleaning.
- **Noise Challenges**: Machine learning pickers must filter out non-tectonic noise typical of the region, specifically **icequakes (iceberg calving)** and **whale calls**.
- **ML Picker Recovery**: Existing ML pickers (OBS Transformer via TensorFlow/SeisBench and INSTANCE in PhaseNet) currently recover only ~40% of the manual catalog, highlighting the need for fine-tuning.
- **Full Pipeline Goal**: Target workflow includes picking, 1D/3D ray-tracing location, and focal mechanism polarity determination.

#### **C. Axial Seamount & Focal Mechanism Determination**

- **Catalog Review**: Reviewed Columbia University's (Felix) Axial Seamount dataset, which utilized fine-tuned PhaseNet (trained on previous AXIAL data), NonLinLoc, and double-difference relocation.
- **Polarity Methods**: Developing two focal mechanism determination methods:
    1. **Cross-correlation-based polarity picking**.
    2. **Machine learning autoencoder-decoder model** paired with HASH / SKHASH.
- **Training & Constraints**: Trained models using synthetics generated from real Axial seismograms combined with site noise. Evaluated pickers include EQTP (SeisBench), PolaCap, CFM, DN, and Ross (2018). Noted that several ML polarity models require long waveform windows (6–10 seconds), rendering them unsuitable for high-frequency accelerometers.

#### **D. Michael — Cascadia OBS & Mount Rainier Nodes**

- **Focus Areas**: Short-period node arrays, picking/association/relocation pipelines at Mount Rainier, and offshore Cascadia OBS datasets.
- **Existing Catalogs**: Incorporating template-matched OBS catalogs (Morton, Trey, Hobit) with local magnitudes, while preparing for multi-span permanent DAS data (8 Hz).

#### **Sangwoo — Association, Relocation & Cross-Correlation Scalability**

- **Location Workflow**: Employs projection-based initial association and location, followed by NonLinLoc refinement using 3D velocity models.
- **Relocation Tool Evaluation**:
    - **HypoDD**: Highly robust, but restricted to 1D velocity models; experiences exponential cross-correlation scaling bottlenecks on large datasets.
    - **GrowClust**: Handles 3D velocity models effectively.
    - **GraphDD**: Uses graph neural networks for large-scale correlation batching, but remains difficult to train.
- **Scalability Mitigation**: To prevent exponential runtime growth during regional cross-correlation, events must be partitioned into spatial/temporal subgroups rather than processed as a single global matrix.

#### **F. Interactive Focal Mechanism & S-Wave Polarization Software**

- **GUI Capabilities**: Demonstrated a custom Python GUI that loads project files, station lists, velocity models, and waveform catalogs.
- **P-Wave & Polarity Picking**: Uses PhaseNet (via SeisBench) for P-picks with manual override support. Integrates **RPNet (Robust Polarity Network)** for polarity determination, as RPNet is resilient against minor errors in P-wave arrival times.
- **S-Wave Vector Polarization**:
    - Incorporates S-wave vector polarizations derived from SV (\(Q\)) and SH (\(T\)) displacement components (filtered at 1–5 Hz / 1–10 Hz on near stations) along with P/S amplitude ratios.
    - Demonstrated that combining P-polarity, P/S amplitude ratios, and S-wave vector polarization dramatically narrows the focal mechanism probability density function (PDF) compared to using P-wave polarities alone.
    - Resolves 180° phase ambiguities using prior radiation pattern constraints derived from P-polarities.
- **SVD Cross-Correlation Alternative (Min)**: Min highlighted a complementary matrix method using Singular Value Decomposition (SVD) on cross-correlation matrices (threshold \(CC > 0.7\) or \(< -0.7\)) to propagate seed manual polarities across large event clusters.

### **3. Science-Grounded Benchmarking Framework Proposal**

- **Community Benchmark Paper**: The Leader proposed a benchmark study assessing ML pickers on challenging, real-world scientific test sequences rather than standard developer metrics.
- **Target Benchmark Sequences**:
    1. **Mainshock-Aftershock Sequences**: M7–M8 mainshocks and early coda aftershocks (e.g., GeoNet New Zealand data on AWS S3, 2023 Turkey M7+ sequence, 2024 Noto Japan earthquake).
    2. **Volcanic & Hydrothermal Swarms**: Fluid-driven and volcano-tectonic swarms (Mount Rainier, Orca Volcano, Axial Seamount).
    3. **High-Density Overlapping Events**: Overlapping event sequences at Axial Seamount.
- **Fine-Tuning Datasets**: The benchmark suite will provide held-out datasets and standardized fine-tuning guidelines for localized model adaptation.

### **4. Cloud Computing Performance & Cost Considerations (QuickScope)**

- **AWS S3 Pipeline**: The `QuickScope` cloud workflow streams data directly from AWS S3, with automated pre-screening for temporary and permanent station metadata.
- **Model Efficiency Comparisons**: Tested PhaseNet, INSTANCE, and GMA (a double-filter Japanese model). Note: GMA increases computation costs by 70% due to larger filter counts without proportional accuracy improvements on test sequences.
- **Model Ensembling Cost Warning**:
    - Inference accounts for **~60% of total execution time** in cloud workflows.
    - Running a single PhaseNet pass globally costs **~$6,000**. Adding a second model for ensembling increases costs by **~$2,000–$3,000** (totaling $8,000–$9,000+).
    - While model ensembling is reasonable for small local runs (~$400), it is cost-prohibitive for large-scale cloud operations.
