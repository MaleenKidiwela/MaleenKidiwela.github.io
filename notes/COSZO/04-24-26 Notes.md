## temporal_anomaly_investigator — Feature additions

Added two switches to `bin/temporal_anomaly_investigator.py` (and supporting change in `bin/diagnose_timing.py`). Committed and pushed to `dev/maleen` — commit `bc25ae1`.

### 1. `--save-nc` (optional local NetCDF download)

- New `save_nc_dir` kwarg on `diagnose_timing.fetch_nc_timestamps`.
- When set, downloads the raw `.nc` via HTTPS (with M2M auth) right after NCML locates it — before the OPeNDAP `Dataset` open.
- Files land in `output/temporal_anomaly/netcdf/` as `<station>_<YYYY-MM-DD>_deployment<NNNN>.nc`. Overwrites on re-run.
- Default off — existing callers in `diagnose_timing.py` unchanged.

### 2. `--only-gaps` (conditional figure generation)

- Previously `collect` mode *always* wrote a 4-panel figure on every successfully processed day.
- Now with `--only-gaps`, the figure is only written when the **post-correction** `n_gaps > 0`.
- CSV row is always written — `figure_generated` column reflects whether the figure was actually produced.
- Skips both cases described by William:
	- Day with no Δi>1 events at all (`n_gaps_raw = 0`).
	- Day where Δi>1 events were reclassified as jitter by the wall-clock check (`wall_clock_clean = True` → `n_gaps = 0`).

### Usage

```bash
# collect a date range, download NetCDFs, only plot real-gap days
python bin/temporal_anomaly_investigator.py --mode collect \
  --start 2019-01-01 --end 2019-03-31 --save-nc --only-gaps
```

### Behaviour matrix

| flags | CSV row | per-day figure | NetCDF saved |
|---|---|---|---|
| (none) | always | always on successful fetch | no |
| `--only-gaps` | always | only if `n_gaps > 0` | no |
| `--save-nc` | always | always | yes |
| `--save-nc --only-gaps` | always | only if `n_gaps > 0` | yes |

## Clarification — gap detection differs from standard pipeline

The gap method in `temporal_anomaly_investigator` is **not** the same as the one in `OOI_data_request_and_convert_mseed.py`. Confirmed after reviewing both.

### Standard pipeline — absolute threshold

1. `dt = np.diff(t)`, strip top 10% → `sp = median(dt_clean)`.
2. Multiplier chosen by sample rate and whether segment is full:
	- sp ≥ 10 s (15 s PREST): 3× or 4× → threshold ~45–60 s
	- sp ≥ 0.5 s: 2.5× or 3.5× → ~2.5–3.5 s
	- sp < 0.5 s: 2.0× or 2.5×
3. Gap = any `Δt > multiplier × sp` (absolute seconds).
4. Purpose: split MiniSEED files at gap boundaries.

### Temporal anomaly investigator — integer-step + wall-clock correction

1. `Δt_FG = median(Δt')` (plain median, no trim).
2. `Δiⱼ = round(Δt'ⱼ / Δt_FG)` — sample-step count.
3. Raw gap = any `Δiⱼ > 1`.
4. Wall-clock correction: if `n_points ≥ span/sp_nominal + 1`, reclassify all Δi>1 as jitter not gaps → `n_gaps = 0`, `wall_clock_clean = True`.

### Practical consequence on 15 s data

- Single missing sample ≈ 30 s. Below the pipeline's 45–60 s threshold → pipeline passes as continuous. Investigator flags `n_gaps_raw = 1`, then wall-clock check decides whether real (`n_gaps = 1`) or jitter (`n_gaps = 0`).
- **Investigator is strictly more sensitive** to single-sample gaps than the pipeline, with jitter discrimination on top.

### Columns in the CSV that expose the distinction

- `n_gaps_raw`, `gap_total_missing_raw` — pre-correction counts.
- `n_gaps`, `gap_total_missing` — post-correction (the values the summary figures use and the ones `--only-gaps` gates on).
- `n_expected_wall` — wall-clock threshold used for the correction.
- `max_abs_epsilon` — rounding-stability sanity check (values near 0.5 mean `Δi` rounding is unstable; `Δt_FG` probably wrong).

## New script — `bin/plot_from_netcdf.py`

Commit `6c5c5f4` on `dev/maleen`. Standalone tool to re-use locally saved NetCDFs without touching OOI.

### Purpose

- Read `.nc` files saved by `temporal_anomaly_investigator --save-nc` (default `output/temporal_anomaly/netcdf/`).
- Reproduce the investigator's 4-panel variability figure + `variability_stats.txt` without re-fetching.
- Optional: convert the NetCDF to MiniSEED using the main pipeline's gap detection + per-segment split logic.
- Does **not** read or modify the collect-mode metrics CSVs.

### Where output lands

- Figures: `output/temporal_anomaly/figures_offline/<station>_<date>/`
	- Separate from collect-mode `figures/per_day/` on purpose — nothing from `collect` is overwritten.
- MiniSEED: `output/temporal_anomaly/mseed/<YEAR>/<NET>.<STA>.<LOC>.<CHA>.<start>-<end>.mseed`

### Re-uses investigator code directly

Imports `compute_variability`, `make_per_day_figure`, `write_stats` from `temporal_anomaly_investigator.py`, so the figure is byte-identical to what `collect` produces. The MiniSEED conversion mirrors the pipeline logic in `OOI_data_request_and_convert_mseed.py` (sample-period from trimmed-median Δt, adaptive multiplier by sp regime, split at `dt > multiplier × sp`, write one MiniSEED per channel × contiguous segment).

### Usage

```bash
# single day, all 3 stations
python bin/plot_from_netcdf.py --date 2019-01-15

# range, one station, with MiniSEED conversion
python bin/plot_from_netcdf.py --start 2019-01-01 --end 2019-01-07 \
    --station RS01SLBS-MJ01A-06-PRESTA101 --convert-mseed

# skip figures, write mseed only
python bin/plot_from_netcdf.py --date 2019-01-15 --no-plot --convert-mseed
```

### Flags

- `--date` XOR (`--start` + `--end`) — required
- `--station` — optional restriction (default: all 3 PREST)
- `--nc-dir`, `--plot-dir`, `--mseed-dir` — path overrides
- `--no-plot` — skip figures
- `--convert-mseed` — also write MiniSEED

### Practical note

If we ever want the generated MiniSEED to be ingested by SeedLink or miniseed2dmc, override `--mseed-dir` to the main pipeline output (`output/mseed/` or `output/mseed2dmc/<YEAR>/`). Today's default keeps it isolated under `output/temporal_anomaly/mseed/` so no pipeline state is affected by offline experiments.

## Migration plan started — `code migration.md`

New living doc at `Obsidian Vault/COSZO/code migration.md`. Captures the plan for replacing the legacy gap detection in `OOI_data_request_and_convert_mseed.py` with the integer-step + true_missing approach. Sections:

- §1 / §1b — corrected mental model (both old and new use day-global sample rate; per-segment is not changing) + end-to-end pipeline walkthrough tagging every step as 🟥 affected / 🟨 indirectly affected / ⬜ unaffected.
- §2 — refined algorithm: replace wall-clock check (param-file dependent) with `true_missing = n_ideal − n_points` (data-derived).
- §3 — risks and edge cases.
- §4 — phased plan: Phase 0 (investigator refactor) → Phase 0b (side-by-side comparison) → Phase 1 (extract `detect_gaps_{legacy,anomaly}`) → Phase 2 (decisions) → Phase 3 (canary cutover, AXBS first) → Phase 4 (cleanup, includes removing pipeline's `save_netcdf`).
- §5 — open questions / decisions log with checkboxes.

### Decisions recorded

- ✓ **Splitting trigger**: Option A — split only when `true_missing > 0`. Jitter-only days produce one MiniSEED for the full day. (Pending William sign-off during Phase 3 canary.)
- ✓ **Sample rate source**: `Δt_true` (OLS slope) used as the day's `sampling_rate`.
- ✓ **NetCDF saving**: investigator-only (via `--save-nc`); pipeline's `save_netcdf` to be removed in Phase 4. Investigator now adopts the server-provided filename convention.
- ✓ **Instability flag**: `jitter_unstable = (frac_maxabs > 0.4)` — sample-rate-agnostic (40 % of `Δt_true`). CSV-only diagnostic, no email.
- ✓ **Email policy**: keep only `sp_deviation` as the algorithm-related email (redefined against `Δt_true`). 6 upstream pipeline emails unchanged. Jitter instability does **not** trigger email.

### Still open

- Action on `jitter_unstable` days beyond the CSV flag (warn-and-write, refuse to write, or fall back to legacy median).
- Whether `true_missing > 0` should also trigger an email.
- Threshold tuning (40 % is a starting guess).
- Deployment-boundary policy when a 24 h window crosses one.
- William sign-off on fragmented MiniSEED + canary station/duration.

## Phase 0 — implemented & validated

Commit `7f961c0` on `dev/maleen`. Investigator refactor + NetCDF filename switch.

### `compute_variability` changes

- Removed `n_expected_wall` and `wall_clock_clean` (param-file-dependent wall-clock check).
- Added `true_missing = max(0, n_ideal − n)` — direct, data-derived missing-sample count from the integer-step reconstruction.
- Added `jitter_unstable = (fmax > 0.4)` — sample-rate-agnostic instability flag derived from `Δt_true` jitter fraction.
- Gap classification now gates on `true_missing == 0` instead of the old wall-clock flag.
- `gap_total_missing` now reports the true count (= `true_missing`) rather than `Σ(Δi−1)` over Δi>1 events. The two can differ when jitter compensates across the day — see SUM1 2025-01-24 below.

### CSV schema

- Dropped: `n_expected_wall`.
- Added: `true_missing`, `jitter_unstable`.
- Kept for auditing: `n_gaps_raw`, `gap_total_missing_raw`, `frac_maxabs`, `max_abs_epsilon`.

### `--save-nc` filename

Switched from `<station>_<date>_deployment<NNNN>.nc` to the server-provided basename (`os.path.basename(netCDF)`). `plot_from_netcdf.find_nc_file` was updated to glob the new pattern first and fall back to the legacy form so older saved files keep working.

### `write_stats` and 4-panel suptitle

- Stats text now surfaces `true_missing` and `jitter_unstable`.
- Suptitle no longer shows `sp_nominal`; `Δt_true` printed at full `repr()` precision (15–17 significant figures) going forward.

## Phase 0 validation — 2025-01-22 → 2026-01-26 collect runs

Ran the investigator on the same dates the pre-Phase-0 archive in commit `f4196b4` covers, then ran the same range a year ahead (2026) for clean-week behaviour. Both runs without `--save-nc`; 2026 with `--only-gaps`, 2025 without (so we kept all the figures).

### Old vs new on identical SLBS dates

| Date | n_points | n_ideal | gap_total_missing (old) | true_missing (new) | n_gaps_raw | jitter_unstable |
|---|---|---|---|---|---|---|
| 2025-01-22 | 86400 | 86400 | 0 | 0 | 0 | False |
| 2025-01-23 | 86400 | 86400 | 0 | 0 | 0 | False |
| **2025-01-24** | **85238** | 86400 | **1162** | **1162** | 3 | False |
| **2025-01-25** | **84396** | 86400 | **2004** | **2004** | 37 | False |
| 2025-01-26 | 86400 | 86400 | 0 | 0 | 1 (jitter) | False — `frac_maxabs = 0.349`, just under 0.4 |

Real-gap days match exactly. Jitter-only day (26) classified as no-gap by both, with the new instability flag `False` because a single 349 ms residual sat just below the 40 % threshold. Threshold validated.

### Where new disagrees with old — SUM1 2025-01-24

| Metric | Value | Note |
|---|---|---|
| n_points | 85308 | |
| n_ideal | 86401 | |
| true_missing | **1093** | n_ideal − n_points |
| n_gaps_raw | 13 | Δi > 1 events |
| gap_total_missing_raw | **1103** | `Σ(Δi − 1)` over those 13 events |

Discrepancy of 10. The legacy algorithm reports 1103 missing (overcount); the new algorithm reports the actual 1093. The difference is jitter intervals that rounded **down** to `Δi=0` elsewhere in the day, compensating for over-rounded gap events. Same pattern on SUM1 2025-01-25 (1809 raw vs 1807 actual — off by 2).

This is the substantive correctness improvement of the new algorithm: it counts samples that are actually missing, not the apparent count from gap events.

### 2026 clean-week run with `--only-gaps`

- 5 days × 3 stations = 15 day-stations, all `true_missing = 0`.
- 0 figures generated (`--only-gaps` correctly suppressed all of them on the clean week).
- CSV rows still recorded with `figure_generated = False`.
- One worth flagging: **SUM1 2026-01-24** had 18 raw `Δi>1` events but `true_missing = 0` with 86401 points. Old absolute-threshold pipeline would split that day into 19 MiniSEEDs; new Option-A logic keeps it as one. Best validation case in the 2026 batch for the splitting decision.

### End-state of `output/temporal_anomaly/`

- CSVs: 10 rows per station (5 from 2025 + 5 from 2026).
- Figures: 15 dirs from 2025 (full coverage); 0 from 2026 (clean week + `--only-gaps`).

## Big run — collect 2016 → 2026

Estimate: ~12 000 day-stations × ~50 s per OOI fetch ≈ **150–170 hours of wall time** (6–7 days continuous). `collect_mode` is idempotent — already-processed `(station, date)` pairs are skipped on resume — so chunking by year keeps progress safe across interruptions.

### Recommended command (local)

```bash
[ -n "$OOI_USERNAME" ] && [ -n "$OOI_TOKEN" ] && echo "creds set" || source .ooi_env

nohup bash -c '
for year in 2016 2017 2018 2019 2020 2021 2022 2023 2024 2025 2026; do
  echo "=== $year start: $(date -u +%Y-%m-%dT%H:%M:%SZ) ==="
  conda run -n ooi_env python bin/temporal_anomaly_investigator.py \
    --mode collect \
    --start ${year}-01-01 --end ${year}-12-31 \
    --only-gaps
  echo "=== $year end:   $(date -u +%Y-%m-%dT%H:%M:%SZ) ==="
done
' > /tmp/collect_2016_2026.log 2>&1 &

echo "PID: $!"
disown
```

### Monitoring

```bash
tail -f /tmp/collect_2016_2026.log
wc -l output/temporal_anomaly/metrics/*.csv
pgrep -af temporal_anomaly_investigator
ls output/temporal_anomaly/figures/per_day/ | wc -l
```

### Interrupt and resume

```bash
pkill -TERM -f 'temporal_anomaly_investigator.py'      # graceful — finishes current day
# or:
pkill -TERM -f 'collect.*2016'                         # kill the year loop too

# resume — same command, skips everything already in the CSVs
nohup bash -c '...same loop...' > /tmp/collect_2016_2026.log 2>&1 &
```

### Things to know

1. **Deployment-boundary day (SLBS / SUM1, 2018)** may produce a garbage row because a single 24 h window can straddle 15 s → 1 s rates. `Δt_FG` lands between the two and the reconstruction breaks. Watch for one bad day around each transition; re-investigate manually after the bulk run.
2. **OOI outages** turn affected days into `has_data=False` rows. After the run, find them with `awk -F, '$4=="False"' output/temporal_anomaly/metrics/*.csv` and re-run that subset.
3. **Disk projection**: CSVs ~5 MB total; figures ~5 MB per real-gap day × ~600 days ≈ 3 GB. No NetCDFs unless `--save-nc` is added.
4. **VM (Kozo)** alternative: swap `conda run -n ooi_env python` for `/home/coszo/miniconda3/envs/ooi_env/bin/python /home/coszo/coszo-data-collection/...`. VM has ~10 GB free; figures would fit, NetCDFs might not.
5. **Sanity check first**: run a single noisy year before committing to the full span:

```bash
nohup conda run -n ooi_env python bin/temporal_anomaly_investigator.py \
  --mode collect --start 2019-01-01 --end 2019-12-31 --only-gaps \
  > /tmp/collect_2019.log 2>&1 &
disown
```

That's ~14 hours and gives a feel for OOI's actual response time before the full 11-year run.

### Default behaviour when running collect mode

Going forward, when running `collect_mode`:

- Always use `--save-nc` so the local NetCDF archive grows alongside the CSVs (the investigator is the canonical place to save NetCDFs after migration; the pipeline will stop saving them).
- Always use `--only-gaps` so figures are produced only when `true_missing > 0`. Clean and jitter-only days get a CSV row with `figure_generated=False` and no figure directory.

Concretely: the standard collect invocation is

```bash
python bin/temporal_anomaly_investigator.py --mode collect \
    --start <YYYY-MM-DD> --end <YYYY-MM-DD> --save-nc --only-gaps
```

The big-run command above omits `--save-nc` only because of the disk hit (~12 000 NetCDFs). For smaller, targeted ranges always include `--save-nc`.
