### 2. Created `testk/` in the Repo

A new folder `coszo-data-collection/testk/` was added with two standalone scripts. These are separate from the main pipeline — they don't use the shell wrappers or cron, and they write to their own output directory.

**`testk/pull_data.py`**
Standalone script that replicates the core data request and conversion logic:
1. Loads OOI credentials from `.ooi_env`
2. Fetches most recent deployment info from the OOI M2M API
3. Submits an async 24-hour data request
4. Polls `status.json` until the job is ready (up to 10 tries, 30s apart)
5. Resolves the NetCDF file location via the NCML manifest
6. Opens the NetCDF via OPeNDAP (no download required)
7. Detects gaps using robust median Δt (same logic as main pipeline)
8. Splits time series at gaps and writes one MiniSEED file per channel per segment
9. Output goes to `testk/output/mseed/`

Reuses from main repo:
- `bin/read_param.py` — parameter file parsing
- `bin/convert_utc.py` — 1900-epoch timestamp conversion (`utcdata1900`)

To run:
```bash
cd coszo-data-collection
conda run -n ooi_env python testk/pull_data.py
```

To change the time window, edit `START_TIME` and `END_TIME` near the top of the script.

**`testk/verify_mseed.py`**
Reads back all `.mseed` files in `testk/output/mseed/` and:
- Prints sample count, start/end times, duration, sampling rate, and data min/max/mean for each file
- Generates a time-series plot saved to `testk/output/verify_plot.png`

To run:
```bash
conda run -n ooi_env python testk/verify_mseed.py
```

Both scripts pushed to `dev/maleen` branch on GitHub.

### 3. How `testk` Differs from the Main Pipeline

| | Main pipeline | testk |
|---|---|---|
| Triggered by | Cron job (daily 18:00) | Manual |
| Time window | Picks up from `run/endtime_*.txt` (continuous) | Hardcoded start/end |
| Output | `output/mseed/` → Ring server → SeedLink | `testk/output/mseed/` (local only) |
| Stations | All stations in one run | One station |
| Error handling | Emails, gap logs, advances endtime file | None |
| Ring server | Required upstream | Not involved |

`testk` is a diagnostic tool — it confirms credentials work, the API responds, gap detection is sound, and MiniSEED files are correctly formed. It is not meant to replace the main pipeline.

### 4. Bug Identified in Main Pipeline

In `bin/OOI_data_request_and_convert_mseed.py`, the channel list selection for the **seedlink** path has a mismatch:

- The pipeline fetches data from the **most recent deployment** (`deployment_id = response.json()[-1]`)
- But channel list selection uses `dep = int(run["deployment"][0])` which is hardcoded to `1` in `run_prest.txt`
- For RS01SLBS and RS01SUM1, deployment 1 has channels `UDO_10/UK1_10` (15s, ended 2018) and deployment 2 has `LDO_10/LK1_10` (1s, still active)
- This mismatch would cause a KeyError when the pipeline tries to read dep-1 variables from a dep-2 NetCDF

**Status: Not yet fixed.** A fix was drafted (use `deployment_id` from the API instead of the run param for seedlink) but reverted pending confirmation from Mika that the API's deployment ID numbering always matches the `channels_<N>` numbering in the param files.
