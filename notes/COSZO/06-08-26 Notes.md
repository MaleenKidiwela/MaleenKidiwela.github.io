### **1. COSZO Tier 1 Sensors & Standard Data Flow**

The ultimate goal of the project is to make over 300 COSZO data channels available on Earth Scope, with some data also stored on the RCA PI NAS. The standard Tier 1 sensors from the COSZO seedling server are already packaged in miniSEED format, making their integration straightforward. These channels will be transferred to Earth Scope using a real-time streaming pathway, which Earth Scope can easily support.

### **2. Handling GSSM and ASCII Data**

A major point of discussion was how to handle ASCII data generated by the GSSM and pressure sensors. These sensors output printable ASCII characters (e.g., 'C' or 'INT') to indicate statuses like GPS 1 PPS health or valve positions.

- **The Problem:** Earth Scope's quality monitoring software historically struggles to process raw ASCII strings embedded in miniSEED channels. While Earth Scope can host "Assembled Data Sets" for raw files, this method lacks proper tooling, restricts findability, and does not support real-time streaming.
- **The Solution:** The team agreed to manually map the ASCII values to integers (e.g., 0 for internal, 1 for seawater). This numerical data will stream via miniSEED, and Dana will include a comment in the StationXML metadata to document the mapping key for end-users.
- **Metadata Requirement:** Earth Scope requires a "Unity nominal response" (a value of 1) to be added to the StationXML metadata for these channels so the system knows to effectively ignore the response field without rejecting the data.

### **3. Format Deprecations & Ring Server Testing**

Earth Scope announced they will **drop support for Antelope ORBs by September 1st**. Moving forward, data must be transferred via a SeedLink ring server.

- **Testing Gen C Formats:** During an upcoming maintenance period at the shore station, Trident and RCA will set up ring servers to test whether Gen C data formats can be successfully ingested and parsed by Earth Scope.
- **Impact:** While COSZO's hydrophone data uses Gen C, it is not currently slated for public release on Earth Scope, minimizing immediate risk for the COSZO project. However, this deprecation poses a potential issue for Neptune data, which relies heavily on Antelope formats, prompting the need for separate testing.

### **4. Managing Multiple Timestamps**

Because remote instruments sometimes have unreliable internal timers, the team wants to preserve both the **instrument time** and the **shore ingestion/acquisition time** for troubleshooting purposes.

- **The Solution:** Instead of trying to inject multiple time flags into a single data stream, they will create separate "engineering" channels specifically dedicated to storing time.
- **Formatting:** These channels will likely use the 'Y' instrument code (e.g., BY1, BY2). The timestamps will be formatted as a 64-bit double float representing seconds since the epoch, pending final compatibility checks with the miniSEED format.

### **5. Logging and Network Configuration**

- **Syslog Server:** Because the GSSM is a read-only device, a Syslog server will be run on the data diversion switch (DDS) side to sync log files over to the PI NAS.
- **IP Addressing:** To maintain separation between the COSZO PI instruments and the main RCA data network, Trident will configure a separate IP address (and potentially a different VLAN in the future) for COSZO's data.
