
Chronos - Finds timing errors
Chronfix - Fixes timing errors using a timing error file for a station
Baros - Applies pressure calibrations using a calibration file for a station

Chronfix would have the following. 

Filtering — multi-pass rolling-median + MAD outlier rejection on the hourly Δt series:
- 3 strict passes at 7-day, 3-day, and 1-day windows.
- 3-point continuity check.
- One looser 10-day pass at the end.
- Result: 673 outliers masked as NaN.

Trigger detection — instead of trying to pick "snap-to-anchor" resyncs, just look at the difference between consecutive
* retained (non-NaN) points. 
* If |Δdt| > 1 s between them, flag the interval `[t(k-1), t(k)]` as a trigger. 
* Merge overlapping intervals. Result: 32 trigger periods.


### one issue related to corrections 

Symptom: corrected hourly peak-lag still showed drift ramps after correction.
Root cause: load_day_z returned just the data array, dropping the trace's UTC starttime. The original pipeline implicitly assumed sample 0 of every daily file = midnight UTC, which was true for original input files but not for chronfix-corrected ones (whose starttime is offset by −Δt

Net effect: re-introducing the same Δt misalignment we'd just removed, so the corrected CCF output looked unchanged.

Fix: trim/pad each loaded trace to span exactly the canonical UTC day with tr.trim(..., pad=True, fill_value=0.0) before returning the data array. Forces sample 0 of every trace to correspond to the same UTC second, regardless of where the input file actually begins or ends. After the fix the validation passes and the closed-loop table reflects the post-fix behaviour.
