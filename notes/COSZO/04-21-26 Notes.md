## Temporal anomaly investigator — tweaks

### Per-day figure layout (`bin/temporal_anomaly_investigator.py`)

Reworked the 2×2 panel figure. Panel C (timestamps vs reconstructed index)
was removed — the OLS line always looks linear at this scale, so it added no
diagnostic value. Split the interval-count histogram into two zoomed views:

| Panel | Content |
|---|---|
| A | Interval count histogram, **Δi' ∈ [0.5, 1.0]**, bin width **0.1**. Shows how tightly the dominant cluster lands on the nominal step. |
| B | Jitter histogram (e_j in ms) — unchanged. |
| C | Interval count histogram, **Δi' > 1.5**, bin width **0.1**. Isolates gap events by size. Shows a placeholder when there are no gaps. |
| D | Residuals e_j (ms) vs reconstructed index i_j — unchanged. |

Rationale: the old single A-panel had to span 0 to whatever the largest gap
was (sometimes Δi ≈ 250), which crushed both the near-1 cluster and the gap
distribution into illegible thin bars. Splitting them at 1.5 lets each view
use its own y-scale and zoom.

### New metric — `n_ideal` (and what it revealed)

Triggered by inspection of **SLBS 2025-01-26**: the CSV said
`n_points = 86400, n_gaps = 1, gap_total_missing = 1`. First reaction:
"how can a day with a missing sample still have 86400 points?"

Added a new metric — `n_ideal` — defined simply as the length of the
reconstructed ideal sample index:

$$
n_{\text{ideal}} = i_{j,\,\text{last}} + 1
$$

For SLBS 2025-01-26, `n_ideal = 86401`.

### The arithmetic doesn't allow a missing sample

Pushed on this and it doesn't hold up:

- first sample `00:00:00.096` → last sample `23:59:59.117`
- wall-clock span ≈ **86399.02 s**
- at `sp_nominal = 1.0 s`, the ideal-grid slot count that physically fits
  in that span is `floor(86399.02 / 1.0) + 1 = 86400`
- we have **86400 samples** → every slot is filled → **no sample is
  actually missing**

So the `n_gaps = 1, gap_total_missing = 1` is a **false positive** from
the rounding rule in Steps 3–4 of the plan.

### Why the plan produces the false positive

`dt_FG = median(Δt) = 1.000590 s` for SLBS that day (larger than the true
1.0 s because of asymmetric jitter). One interval in the file is probably
≈ **1.5 s** — a jitter event, not a dropout. Its normalised step count is
`Δi' = 1.5 / 1.000590 ≈ 1.499`. If that value tips just above 1.5 it
rounds to 2 (flagged as a gap); just below 1.5 it rounds to 1 (no gap).
The classifier is brittle at the Δi = 1.5 boundary.

The OLS fit confirms the grid has been stretched to absorb the fake extra
slot: `Δt_true ≈ 0.999989 s` (we only print 6 decimals, so it looks like
1.000000). That sub-1.0 slope lets 86401 slots fit into 86399 s.

So `n_ideal = 86401` is arithmetically consistent with the reconstructed
grid but **misleading as "samples the day should have held"** — it
inherits the rounding artifact.

### Two possible fixes

1. **Wall-clock cross-check.** Compute
   `n_expected_wall = round((data_end − data_start) / sp_nominal) + 1`.
   If `n_points == n_expected_wall`, suppress the spurious gap flag.
2. **Tighter gap criterion.** Only call it a gap when
   `Δt > 1.5 × sp_nominal` *and* `Δi_int > 1`, using `sp_nominal` instead
   of the noisy median `dt_FG`.

Decision pending — will pick one before re-running collect.

n_ideal = 86400 — same as n_points.                                                                                                 

This is actually interesting and contradicts my earlier arithmetic. I was assuming n_ideal = n_points + gap_total_missing = 86401, but the actual  reconstructed index length is 86400.        

The explanation: somewhere in the day there's also at least one interval where Δi' rounds to 0 (two samples very close together, Δt < 0.5 × dt_FG). Those cancel the Δi = 2 event, so the net sum of Δi_j is 86399 → i_j[-1] = 86399 → n_ideal = 86400.                                                  
  
So the plan's rounding scheme is producing a paired artifact: one spurious "gap" (Δi=2) somewhere, paired with a spurious "overlap" (Δi=0) somewhere else. Net: no missing samples, which matches the wall-clock arithmetic. n_gaps = 1, gap_total_missing = 1 is misleading on its own — and n_ideal =  86400 is what actually tells you the day is whole.

Observations:

- 01-22 and 01-23 are clean across all stations (0–1 gaps each, σ ≈ 3 ms).

  n_points = n_ideal = 86400, i.e. no actual missing sample.
