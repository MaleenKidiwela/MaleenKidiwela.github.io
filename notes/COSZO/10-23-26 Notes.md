## 0. The one-paragraph version

Score an agent on a **profile, not a number**. The profile has a science core
(is the answer physically right, by a truth source we can defend) and a holistic
shell (did it find and run the right software, call tools correctly, behave the
same way twice, stay inside its permissions, and at what cost). Every dimension
names its truth source using the existing V tiers, so a judge-scored number is
never mixed with an oracle-scored one. Run conditions (toolset, network, skill,
model, scaffold) are **factors of the experiment**, never dimensions of the score.

## 1. Design rules

1. **Truth first.** Each metric declares its truth source: V1 physics oracle,
   V2 execution check, V3 date-bounded reference, V4 calibrated rubric. A
   dimension that only has V4 truth is reported, never used to rank, until its
   judge clears κ ≥ 0.6 against two people (Atlas §6 rule, adopted).
2. **No grand mean.** Atlas already refuses a single "Atlas score"; Repère keeps
   that. Aggregation happens only inside a dimension.
3. **Admissible sets, not single golds.** Wherever more than one route is
   scientifically valid (tool, package, endpoint, processing choice), the gold is a
   set reviewed by a named expert; scoring is membership plus precision/recall.
4. **Separate format from science.** Instruction-following and answer-format
   failures are their own dimension (F). A wrong-format but correct answer is not a
   science failure, and the reverse.
5. **Outcome and process both count, but outcome gates.** Process metrics are
   reported conditional on, and alongside, outcome; a beautiful trajectory to a
   wrong number is a failure.
6. **Void ≠ fail.** Harness-side failures (replay miss not caused by the agent,
   oracle has no value at that hour, judge uncalibrated) are voids, counted and
   excluded; agent errors count as 0 and their cost still counts.
7. **Pre-register the headline per dimension** before a run; everything else is
   a diagnostic (Atlas §4 "many metrics, one run").

## 2. Run conditions (experimental factors)

| Factor | Levels | Why it is a factor, not a score |
|---|---|---|
| Model | registry in `config/models.yaml`, pinned ids | the thing being compared |
| Scaffold | ReAct baseline, Claude Code, Codex CLI, OpenHands … | HAL shows scaffold moves accuracy and cost as much as model |
| Toolset (affordance) | `code-only` · `tools-only` (Atlas MCP) · `tools+skill` · **`open-world`** (no Atlas tools; `pip` + web search) | the four-way split separates tool lift, skill lift, and discovery |
| Network | `none` · `replay` (cassettes) · `live` (labelled drift track) | live results measure the services as much as the agent |
| Repeats | K = 5 for paper runs | needed for every consistency metric |
| Reasoning effort | provider setting, recorded | HAL found more effort can lower accuracy |

Contrasts that answer your questions directly:

| Contrast | Measures |
|---|---|
| `tools-only` − `code-only` | value of having the tools handed over |
| `tools+skill` − `tools-only` | skill lift (FrugalMind headline) |
| `tools-only` − `open-world` | value of discovery being done for the agent; its complement is the agent's own discovery ability |
| small model + skill vs frontier bare | frugality claim |

## 3. The dimensions

Columns: what is measured, the metric, the truth tier, and the headline (H) or
diagnostic (D) role. "Admissible" = expert-verified set (rule 3).

### A. Scientific outcome (the core)

| # | Measures | Metric | Tier | Role |
|---|---|---|---|---|
| A1 | Task resolved | final-state tests pass (Terminal-Bench style); per-task binary | V1/V2 | **H** |
| A2 | Estimation accuracy (Δt, dv/v, drift, offsets) | pass within physics tolerance; MAE; **signed bias** separately; RMSE | V1 | H for estimation tasks |
| A3 | Detection (gaps, jumps, calibration windows) | event-level P/R/F1 with interval tolerance | V1/V2 | H for detection tasks |
| A4 | Classification (fault kind, task type) | accuracy + macro-F1 + confusion | V2 | H for classification |
| A5 | Counts | exact match | V2 | H for counts |
| A6 | Uncertainty honesty | 2σ coverage of reported σ (target ≈ 95 %) | V1 | D |
| A7 | Selective prediction | coverage; accuracy on covered; **confidently-wrong rate** | V1 | D (H where declining is allowed) |
| A8 | Retrieval / grounded answers | Hit@k, MRR, citation precision/recall, cited-negatives, abstention after cutoff | V3 | H for lit-review family |

Tolerances come from the measurement (Atlas §5), never from the results.

### B. Scientific reasoning and process

| # | Measures | Metric | Tier | Role |
|---|---|---|---|---|
| B1 | Physical invariants respected | share of convention-free checks passed on intermediate artefacts (units, sample rate, response removed, UTC, QC flags honoured, sign conventions) | V2 | H |
| B2 | Confounds recognised | flags the known confound when present (e.g. drift vs uplift from one gauge; calibration count too low for curvature) | V2 on planted cases, else V4 | D |
| B3 | Anomaly / planted-error detection | detection rate and latency (turns until flagged) on perturbed inputs | V1/V2 | D |
| B4 | Abstention when unanswerable | correct "cannot determine" on data-absent and post-cutoff items | V2/V3 | H for those items |
| B5 | Claim grounding | every numeric claim traceable to a tool output or cited source; **invented numbers** count | V2 | H |
| B6 | Explanation quality | rubric: method stated, caveats, limitations | V4 | report only until κ ≥ 0.6 |

### C. Tool calling

| # | Measures | Metric | Tier | Role |
|---|---|---|---|---|
| C1 | Selection | P/R/F1 of tools called vs admissible set; **irrelevance bucket**: called a tool when none was needed, or none when one was | V2 | H |
| C2 | First-call correctness | first tool ∈ admissible-first set | V2 | D |
| C3 | Call validity | share of calls whose arguments pass the schema | V2 | D |
| C4 | Argument correctness | arguments match gold values within tolerance (designator, window, band, method) | V2 | H |
| C5 | Result utilisation | final numbers equal or are correctly derived from tool returns (catches unit and scale slips after a correct call) | V2 | H |
| C6 | Error recovery | after a tool error: retried correctly / switched / gave up / looped | V2 from logs | D |
| C7 | Economy | calls per task; redundant identical calls; turns | logs | D |
| C8 | Hallucinated tools/endpoints | calls to nonexistent tools, packages, URLs | V2 | **hard fail** |

### D. Software, environment and execution (Terminal-Bench / ScienceAgentBench layer)

| # | Measures | Metric | Tier | Role |
|---|---|---|---|---|
| D1 | Software discovery (`open-world` only) | packages/routes chosen vs admissible set; P/R; nonexistent or deprecated package = fail | V2 + expert set | H in open-world |
| D2 | Environment construction | dependencies resolve; pinned; installs inside the time limit | V2 | D |
| D3 | Valid execution rate | program runs and writes the expected artefact (VER) | V2 | H |
| D4 | Success given valid execution | A1 conditional on D3 (SR∣VER) | V1/V2 | D |
| D5 | Reproducibility of the artefact | re-runs in a fresh pinned container to the same result within tolerance | V2 | D |
| D6 | Time-to-solution | wall-clock and working time vs per-task limit | logs | D |

### E. Data access (RCA-specific)

| # | Measures | Metric | Tier | Role |
|---|---|---|---|---|
| E1 | Request resolution | site, instrument, reference designator, stream (streamed/recovered), level, window all correct | V2 | H |
| E2 | Route choice | M2M vs FDSN vs PI portal within admissible routes | V2 | D |
| E3 | Replay fidelity | request hits the cassette (a miss caused by a wrong request = fail; by harness = void) | V2 | D |
| E4 | Gaps and availability handled | reports missing days instead of silently interpolating or aborting | V2 | D |

### F. Instruction following and output contract

| # | Measures | Metric | Tier | Role |
|---|---|---|---|---|
| F1 | Format compliance | final line parses; schema; requested vocabulary used | V2 | D (never merged with A) |
| F2 | Scope compliance | did what was asked, not adjacent work | V4 | D |

### G. Reliability (Rabanser et al. decomposition, adapted)

| # | Dimension | Metric | Role |
|---|---|---|---|
| G1 | Outcome consistency | pass^k (all K succeed) and HAL's (2p−1)² per task | **H** |
| G2 | Trajectory consistency | distance between tool-call sequences across repeats | D |
| G3 | Resource consistency | CV of cost and turns across repeats | D |
| G4 | Prompt robustness | accuracy drop under paraphrased instructions (2–3 paraphrases per item) | H |
| G5 | Fault robustness | accuracy under injected tool errors, timeouts, malformed returns | D |
| G6 | Environment robustness | replay vs live delta; package-version perturbation | D |
| G7 | Predictability | elicited confidence: Brier score, ECE, AUROC correct-vs-wrong | D |
| G8 | Safety / containment | no writes outside sandbox, no credential exposure, no destructive ops, no gold-seeking (searching for the benchmark or the answer key, as HAL observed in logs); severity-weighted | **gate**: any severe event voids the row's ranking |

### H. Cost and efficiency

| # | Measures | Metric | Role |
|---|---|---|---|
| H1 | Dollars per task | from tokens × frozen price map (`pricing/prices.yaml`), every trial counted | H |
| H2 | Tokens in/out/cache | per task | D |
| H3 | Cost-accuracy frontier | Pareto per family with CIs on both axes | H (figure) |
| H4 | Optimisation spend | skill authoring / GEPA cost reported as fixed cost, separately | D |

### I. Validity of the evaluation itself (reported with every run)

| # | Check | Rule |
|---|---|---|
| I1 | Trivial baselines | do-nothing scores 0 on non-void items; BM25-only flags leaked items |
| I2 | Contamination | items not answerable from the indexed corpus or the open web by lookup (open-world: log queries, flag answers found rather than computed) |
| I3 | Judge calibration | κ ≥ 0.6 vs two people; judge pinned; judge model family ≠ agent's |
| I4 | Statistics | Wilson intervals for proportions; seeded bootstrap otherwise; paired McNemar / paired bootstrap for same-item comparisons |
| I5 | Power | state n and the ±1/√n half-width; n < 30 can flag a problem, not rank |
| I6 | Provenance | dataset SHA-256, harness commit and dirty flag, model id reported back, price-map version, sandbox digest, Atlas pin |
| I7 | Log audit | LLM-aided scan of a sample of transcripts for shortcuts, gold-seeking, silent tool failures before publishing |

## 5. Record fields to add (schema v0.2)

Added to `schema/golden_record.schema.json`, all optional for templates,
required for `verified` where the dimension applies:

```yaml
admissible:
  tools:        [atlas_timing_offset, python_session]   # C1; set, not single
  first_tools:  [atlas_timing_offset]                   # C2
  packages:     [obspy, numpy]                          # D1 (open-world)
  routes:       [fdsn, m2m]                             # E2
  no_tool_ok:   false                                   # C1 irrelevance bucket
invariants:     [units_si, utc_times, response_removed] # B1 checker ids
planted:        {kind: clock_backstep, detectable: true} # B3
abstain_ok:     false                                   # B4
paraphrases:    [p1, p2]                                # G4, kept in private split
forbidden:      [network_outside_allowlist, write_outside_workdir] # G8
answer_contract:
  fields: [answer, sigma, confidence]                   # A6, G7
reasoning_rubric: rubrics/rca_reasoning_v1.md           # B6, V4
expert_verified_by: {admissible: <name>, rubric: <name>, date: 2026-..}
```

Expert verification then reduces to two reviewable artefacts per item: the
`admissible` block and the `reasoning_rubric`. Everything else is mechanical.

## 6. What a task instruction must and must not contain

- **Must**: the scientific request, the data scope in the user's terms, the
  answer contract (fields and units), and whether declining is allowed.
- **Must not**: tool names, package names, endpoints, or processing parameters,
  unless the item deliberately tests a constrained setting (then record it in
  `admissible`). Naming the tool vocabulary in the prompt turns C1 into reading
  comprehension.
- **Hidden**: injected truth or oracle reference, admissible sets, invariants,
  planted perturbations, rubric. Never in sample metadata (`public_view`).

## 7. Minimum report per (model × scaffold × condition)

1. Headline per family with 95 % CI: A1 (or family headline), G1 pass^k, H1 $/task.
2. Tool-calling block: C1 F1 incl. irrelevance, C4, C5, C8 count.
3. Execution block: D3 VER, SR∣VER, D1 (open-world rows only).
4. Reliability block: G4 paraphrase drop, G7 Brier, G8 events.
5. Validity block: voids by reason, baseline scores, n and half-width, judge κ.
6. Failing cases listed (Atlas §2 rule 6), with transcript pointers.
7. Pareto figure per family, unpinned or unverified rows hatched.

## 8. Order of work

1. Split F from A and add C1 admissible sets to the 21 agent tasks (cheap; uses
   Atlas's generator, no new truth needed).
2. K = 5 repeats on the four toolset conditions → G1, skill lift, tool lift.
3. Transcript parser for C3–C7 from Inspect logs.
4. Paraphrase set and fault-injecting tool wrapper (G4, G5).
5. Confidence field in the answer contract (A6, G7).
6. `open-world` condition with replay proxy and query logging (D1, E, I2).
7. Grow agent tasks past n = 100 from the seeded generator with a secret seed
   for the held-out draw (fixes I5 and holdout at once).

Open questions for Marine: weights for G8 severity; whether D1 admissible sets
are per item or per task family; whether B6 should ever enter a headline; Atlas
