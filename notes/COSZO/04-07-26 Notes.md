## Pipeline Overview

The repository has two parallel workflows running per station:

| | Seedlink (real-time) | miniseed2dmc (historical) |
|---|---|---|
| Purpose | Near-current data | Historical backfill |
| Triggered by | Cron job, daily 18:00 window | Cron job, every 2 min outside daily window |
| Output directory | `output/mseed/` | `output/mseed2dmc/<YEAR>/` |
| Log directory | `log/` | `log_mseed2dmc/` |
| Endtime file | `endtime_..._prest.txt` | `endtime_..._prest_mseed2dmc.txt` |
| Deployment selection | Most recent (API `response.json()[-1]`) | From `run["deployment"][0]` in run_prest.txt |
| Downstream | Ring server → SeedLink → EarthScope | Manual `mseedtodmc` command |

Both paths call the same Python script with different arguments:
```bash
python bin/OOI_data_request_and_convert_mseed.py <station> prest <seedlink|miniseed2dmc>
```

## Mika's Response & Deployment Bug Fix

Heard back from Mika confirming:

1. **API deployment ID always matches param file numbering** — `deployment_id = 2` from the API → safely look up `channels_2`. Fix is safe to apply.
2. **Seedlink did run successfully on the VM for deployment 2** — the bug was dormant because the sloppy deployment variable block predated the `transfer_method` argument.
3. **Seedlink has never run with deployment 1** — only dep 2 (current).

### Fix Applied to `bin/OOI_data_request_and_convert_mseed.py`

**1. Cleaned up the deployment info block** (Mika's suggestion):
```python
# After (clean):
if transfer_method == 'seedlink':
    deployment_id = response.json()[-1]
elif transfer_method == 'miniseed2dmc':
    deployment = int(run["deployment"][0]) - 1
    deployment_id = response.json()[deployment]
```

**2. Channel list now uses correct deployment per transfer method:**
```python
if transfer_method == 'seedlink':
    dep = deployment_id              # from API — matches channels_N in param file
else:
    dep = int(run["deployment"][0])  # from run_prest.txt — for historical backfill
```
Same fix applied to the sample-rate alert block.
