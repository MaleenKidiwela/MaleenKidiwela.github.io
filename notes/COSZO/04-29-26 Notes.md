## Continuity advance switched to `request_end_time`

Replaced the legacy `next_start = last_written + sp` formula with `next_start = UTCDateTime(end_time)` (commit `57a703d`). Each cron run now advances `endtime_*.txt` by exactly 86400 s — completely independent of any per-day rate estimate (median Δt or OLS Δt_true).

**Why:** Δt_true varies day-to-day (sub-ms typically), so using today's value to predict tomorrow's first sample was a small extrapolation that *could* drift over time. Walking arithmetic across day boundaries also coupled the cron's continuity to the algorithm choice. Removing the dependency means the cron's day-stride is structurally fixed: 86400 s, every run, forever.

**Tradeoff (consistent with "gaps are honest"):** if a window only got partial data, the next cron jumps straight to the next calendar day instead of re-fetching from where partial data ended. Missing portions become permanent gaps in the archive rather than getting silently backfilled with a different timestamp.

**Verified end-to-end** by manually setting SLBS `endtime_*_mseed2dmc.txt` to `2016-01-01T00:00:00.000000Z` and running the pipeline once:

```
[CONTINUITY] last_written=2016-01-01T23:59:51.793466Z → next_start=2016-01-02T00:00:00.000000Z (= request end_time)
endtime_RS01SLBS-MJ01A-06-PRESTA101_prest_mseed2dmc.txt set = 2016-01-02T00:00:00.000000Z
```

The post-run endtime is exactly +86400s from the pre-run endtime, both calendar-aligned. Independent of the actual last sample timestamp (`23:59:51.793` here).

## New script — `bin/backfill_mseed_from_nc.py`

Commit `14e924a`. Standalone one-shot tool for historical backfill **on a local machine, not a cron pipeline**. Lets us avoid re-hitting OOI for the historical range we already have NetCDFs for (via `temporal_anomaly_investigator --save-nc`).

### What it does

- Walks `output/temporal_anomaly/netcdf/` and matches each (station × date) NC.
- Opens each NC, runs `detect_gaps(algo, ...)` from `bin/gap_algorithms.py` (same code path the cron uses).
- Writes one MiniSEED per (channel × contiguous segment) into `output/mseed2dmc/<YEAR>/`.
- Filename + record-length conventions are byte-identical to what the cron produces.
- Optionally (`--append-stats`) appends a row per (station, date) to `output/metrics/<station>_prest_pipeline_stats.csv`, idempotent on the (station, date) key.

### Coexists with the cron

- The VM cron pipeline is **unchanged** — it still hits OOI live, advances `endtime_*.txt` by 86400 s, writes to `output/mseed2dmc/<YEAR>/`.
- The backfill script writes to the **same** output path with the **same** filename convention. So the two workflows feed the same archive without conflict.
- The cron's per-day CSV idempotency check (`metrics_row_exists`) means rows written by the backfill won't get duplicated when the cron later catches up to those dates.

### Usage

```bash
# All 3 stations, full historical span we have NCs for
python bin/backfill_mseed_from_nc.py --start 2014-09-14 --end 2026-03-01 --append-stats

# One station, anomaly algorithm (offline canary equivalent)
python bin/backfill_mseed_from_nc.py --start 2025-01-01 --end 2025-01-07 \
    --station RS01SLBS-MJ01A-06-PRESTA101 --gap-algo anomaly --append-stats

# Sandbox — no side effects on the production output dirs
python bin/backfill_mseed_from_nc.py --date 2015-01-30 \
    --mseed-dir /tmp/test_mseed --metrics-dir /tmp/test_metrics --append-stats
```

### Flags

- `--date` XOR `--start` + `--end` — required
- `--station` (repeatable) — restrict to one or more stations; default: all 3 PREST
- `--gap-algo {legacy,anomaly}` — default `legacy`
- `--nc-dir`, `--mseed-dir`, `--metrics-dir` — path overrides
- `--append-stats` — also write per-day CSV rows
- `--no-skip` — re-process days already in the metrics CSV (default: skip)

## Plan going forward — backfill is local-only

Since the investigator already runs locally and is saving NetCDFs + computing variability stats for the full historical range, **the backfill no longer needs to be done by the VM cron**. The local script handles MiniSEED conversion only:

- **No NC saving by the backfill script** — the investigator's `--save-nc` already produces them.
- **No per-day stats CSV from the backfill** — the investigator's `<station>_variability.csv` already covers historical data quality auditing. The pipeline-side `pipeline_stats.csv` only matters for forward (cron-driven) operations.
- **Backfill's only job:** convert NCs → MiniSEEDs under `output/mseed2dmc/<YEAR>/` using the same gap detection + filename convention the cron uses. So the historical archive looks identical regardless of who wrote it.

### Concrete invocation

```bash
python bin/backfill_mseed_from_nc.py \
    --start 2014-09-14 --end <wherever the investigator collect run has reached>
```

Default flags only — no `--append-stats`, no `--save-nc`. Just NC→MiniSEED conversion in the cron-format output path.

### Resulting workflow split

| Source | Time range | Outputs |
|---|---|---|
| Investigator (local) | full historical (2014→present) | variability CSV, NCs, optional figures |
| Backfill script (local) | full historical (where NCs exist) | MiniSEEDs in `output/mseed2dmc/<YEAR>/` |
| Cron pipeline (VM) | forward-only from wherever backfill ended | live MiniSEEDs, `pipeline_stats.csv` rows, `output/diagnostics/` events |

VM cron's `endtime_*.txt` gets set to one day after the local backfill's last processed date. Cron picks up live from there.
