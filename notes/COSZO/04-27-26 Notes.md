# Building a RAG chat over my notes site

I built a password-gated chat that answers questions grounded in the notes I publish from this vault, then generalized it so anyone using the `vaultnotes` package can opt in with one command. Live at https://maleenkidiwela.github.io/chat/.

Implementation walkthrough: [[RAG implementation]]. The vaultnotes generalization happens later in [[05-03-26 Notes]].

This is a test that could be implemented later for COSZO documents after the Science Advistory Committee meeting plans [[04-23-26 Notes]]
## What it does

Anonymous visitors keep browsing the notes site normally. Behind a shared password, `/chat/` opens a conversational UI that retrieves the most relevant chunks of my notes and asks Gemini to answer using only those chunks, citing notes by title.

## Architecture

```
Obsidian vault
   |  vaultnotes sync (or daily 5 PM launchd)
   v
pages-repo (notes/COSZO, notes/BransfieldEQ, notes/Earthnote)
   |  git push to main
   v
GitHub Actions: Build RAG index
   - chunks markdown (~500 tokens, 100 overlap)
   - embeds chunks via gemini-embedding-001 (768d, L2-normalized)
   - writes public/{search-index.json, chunks.json, embeddings.bin}
   - commits public/ back to main
   v
GitHub Pages serves static site + index files + chat UI
   |
   |  fetch (browser)
   v
Cloudflare Worker (notes-rag.quakehunt.workers.dev)
   - constant-time password check
   - holds GEMINI_API_KEY and CHAT_PASSWORD as Worker secrets
   - retries 429/503 with backoff
   - streams gemini-2.5-flash-lite via SSE
```

No database, no accounts, no per-user state.

## The three pieces

### 1. Indexer — `scripts/index-notes.mjs`

Runs in GitHub Actions on every push that touches `notes/**` or the script itself. Walks the published project folders, strips markdown, splits into ~500-token chunks with ~100-token overlap, and embeds them with `gemini-embedding-001` at 768 dimensions. Embeddings are L2-normalized so cosine similarity in the browser is just a dot product.

Outputs:
- `public/search-index.json` — serialized MiniSearch index (BM25)
- `public/chunks.json` — chunk metadata (id, noteId, title, url, text)
- `public/embeddings.bin` — concatenated `Float32Array`, ordered by chunk id

> [!note] The Action commits `public/` back to `main` and Pages auto-redeploys. New notes are answerable within ~2–3 minutes of the daily sync push.

### 2. Worker — `worker/src/index.js`

A tiny Cloudflare Worker that proxies Gemini. Two endpoints:

- `POST /embed` — embeds a query string with `taskType: RETRIEVAL_QUERY`. The frontend calls this once per question, plus once on password entry as a verification ping.
- `POST /chat` — takes the user query and pre-assembled context, streams `gemini-2.5-flash-lite` SSE back to the browser.

Other things the Worker does:
- **Constant-time password check** so the password isn't string-equality-compared.
- **CORS locked to the Pages origin** so the API key isn't trivially abusable from elsewhere.
- **Length caps** (2000 chars for query, 20000 for context) to keep prompts well-bounded.
- **Retry with exponential backoff** on 429 and 503, honoring `Retry-After`. This was needed because Gemini's free tier 503s under demand spikes, and the chat felt broken without the retry.

### 3. Frontend — `chat/{index.html, chat.js, chat.css, fox.svg, fox-anim.png}`

Three screens:

1. **Password gate** — single input. Password is held only in memory; refresh forgets it. Submitting calls `/embed` with a "ping" text; if the Worker returns 200, password is correct and we swap to chat.
2. **Loading** — fetches `search-index.json`, `chunks.json`, `embeddings.bin` in parallel.
3. **Chat** — message list with a streaming response panel and a pixel-fox avatar that walks through 4 frames.

Hybrid retrieval pipeline on every question:

```js
async function ask(query) {
  const queryEmb = await fetchEmbedding(query);                 // via Worker
  const bm25 = miniSearch.search(query).slice(0, 10);            // keyword
  const semantic = cosineTopK(queryEmb, embeddings, 10);         // vector
  const fused = reciprocalRankFusion(bm25, semantic, 5);         // merge
  const context = fused.map(c => `### ${c.noteTitle}\n${c.text}`).join('\n---\n');
  streamChat(query, context, onToken);                           // via Worker
}
```

[Reciprocal Rank Fusion](https://learn.microsoft.com/azure/search/hybrid-search-ranking) handles the BM25-vs-semantic blending without needing tuned weights. Top 5 fused chunks make up the context window passed to Gemini.

Citations are deduped by note and shown as clickable chips below each answer, linking to the raw `.md` URL.

## Data flow on one question

1. Browser does `MiniSearch.loadJSON(...)` and wraps `embeddings.bin` as a `Float32Array`.
2. User types question → frontend calls Worker `/embed` to get the query vector.
3. Worker validates password, hits Gemini `embedContent`, returns 768 floats.
4. Frontend runs BM25 + cosine top-K locally, fuses with RRF, picks top 5.
5. Frontend posts `{query, context}` to Worker `/chat`.
6. Worker validates password, opens streaming Gemini call with system prompt + user content, pipes the SSE body straight back.
7. Frontend parses SSE events (`data: {...}\n\n`), appends each text token to the assistant bubble, renders citation chips.

Total wall-clock to first token on WiFi: ~1–2s when Gemini isn't throttling.

## Daily operations

- **Adding notes** — edit them in Obsidian. The launchd job at 5 PM rsyncs published folders into `pages-repo` and pushes. The Action sees `notes/**` changed, rebuilds the index, commits `public/`, Pages redeploys. Done.
- **Adding a folder** — `vaultnotes add NewFolder`. It edits config, syncs, and the indexer picks up the new folder via `rag-config.json`.
- **Worker code changes** — git push does *not* update the Worker. Run `vaultnotes rag deploy-worker` (or `npx wrangler deploy` from `worker/`).
- **Rotating the password** — `npx wrangler secret put CHAT_PASSWORD` from the worker dir, then `npx wrangler deploy`. Frontend doesn't need any change.

## Generalized into the vaultnotes package

Once the chat worked for me, I lifted the whole thing into `vaultnotes` so other users get it for free. The new surface area:

- `vaultnotes rag enable` — copies `chat/`, `worker/`, `scripts/`, `.github/workflows/build-index.yml`, `package.json`, `rag-config.json`, `chat/config.json` into the user's pages repo. Worker name and CORS origin are derived from `github.repo`.
- `vaultnotes rag secret <NAME>` — wraps `wrangler secret put` with the right cwd.
- `vaultnotes rag deploy-worker` — runs `npm install` (one-time) + `wrangler deploy` from the worker dir.
- `vaultnotes rag set-worker-url <url>` — stores the deployed URL in YAML config and `chat/config.json`.
- `vaultnotes where [--open]` — prints (and optionally reveals in Finder) the local pages-repo path. Necessary because the default lives at `~/.local/share/vaultnotes/pages-repo` which Finder hides.
- `vaultnotes upgrade` — wraps `pipx install --force git+https://github.com/MaleenKidiwela/vaultnotes.git`.

The indexer in the package reads project folders from `rag-config.json` instead of hardcoded names. `vaultnotes sync` regenerates that file on every run, so each user's chat tracks their own published folders.

## Costs and quotas

- **Embedding** — runs once per chunk, only on changed pushes. ~140 chunks for my vault costs essentially nothing on free tier. Even at 10× the size, paid-tier embedding is a few cents per rebuild.
- **Chat** — `gemini-2.5-flash` free tier is 20 requests/day. After hitting that limit on the first day of testing, I switched to `gemini-2.5-flash-lite` which gets ~1000 RPD free and is plenty for grounded RAG answers. The model gap matters less here because the answer is already grounded in retrieved text — the model is summarizing, not recalling.

## Gotchas worth remembering

- `gh repo create <name> --clone -- <path>` is invalid; only one positional. Split into `gh repo create <name>` then `gh repo clone <name> <path>`.
- `display: flex` overrides the browser default for `[hidden]`, so password screen stayed visible after success until I added `[hidden] { display: none !important }`.
- Free-tier Gemini 503s during overload are common; Worker-side retry with `Retry-After` makes the chat feel reliable.
- Pixel-art sprite frames need a *single* scale factor and baseline across all frames, otherwise the character visibly grows and shrinks between poses. Solution: take the union bbox across all frames, crop each frame to it, then scale everything by one factor.
- When `vaultnotes sync` runs, only files you explicitly `git add` get pushed. Forgot to add the RAG files in the first version, so the chat folder existed locally but never reached the remote — easy to miss.
