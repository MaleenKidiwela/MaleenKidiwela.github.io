### Key Technical Details

**Data Conversion Process:**

1. Request data via M2M (machine-to-machine) from OOI database
2. Calculate daily sample rate (to handle timestamp jitter)
3. Convert NetCDF to MiniSeed format
4. Detect gaps and create separate files per segment
5. Move to appropriate output folder

**Channel Codes:** [[non_tier1_ooi_instrument_data_notes]]
- Pressure: LDO (L=1Hz, D=pressure, O=outside)
- Temperature: LK1 (K=temperature, 1=internal)

**Parameter Files Required:**

- Station parameters (network/station info)
- Channel parameters (deployment dates, sensor IDs, channel codes)
- Run parameters (time intervals, deployment numbers)

## Technical Notes

**Code Structure:**

- `OOI_data_request_and_convert_miniseed.py`: Main data request/conversion


**Code Architecture:**

- **Entry point:** `run_OOI_request.sh` - sets Python environment and pulls OOI credentials securely
- **Dispatcher:** `run_data_collection.sh` - routes to metadata or data request code based on arguments
- **Arguments structure:**
    - Data requests: `[station_identifier] press [seedlink/miniseed_to_dmc]`
    - Metadata: `all press metadata`

**Gap Detection & File Management:**

- Code automatically detects data gaps and creates separate MiniSeed files per continuous segment
- EarthScope recognizes gaps by comparing start times between sequential files
- Gap information logged in `log/` directory
- Logs also track: failed requests, undersized data returns, and gap locations

**Sample Rate Calculation Issue (Resolved):**

- Previous implementation incorrectly calculated sample rates due to timestamp jitter
- Created hundreds of files (one per sample) instead of continuous segments
- Mika deleted all EarthScope data and restarted from scratch
- Current implementation uses daily sample rate calculation for robustness

**File Size & Storage:**

Based on the meeting discussion, the `ring.conf` file is the configuration file for the Ring server, located in the `conf/` directory on the COSZO virtual machine.

**Key Configuration Details:**

The file specifies that the Ring server uses the **"MiniSeed_scan"** method, which:

- Scans the MiniSeed folder (`output/MiniSeed/`) for new data files
- Loads the data into the "ring" (an in-memory buffer)
- Makes the data available for EarthScope's SeedLink client to retrieve

**How It Works:**

When data files are placed in the MiniSeed folder, the Ring server:

1. Detects the new files through the scan method
2. Loads them onto the ring buffer
3. EarthScope's client reads from this ring and archives the data

**Important Note:**

The final line in `ring.conf` contains the MiniSeed_scan configuration that points to the MiniSeed folder path. This is what enables the automatic detection and transfer of pressure gauge data to EarthScope.

Mika mentioned there's additional documentation about Ring server configuration in the COSZO Drive under "Non-Tier 1 Data Flow" if you need more detailed information about other settings in the file.
