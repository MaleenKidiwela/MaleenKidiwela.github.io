Lets fix the remaining issues in the metadata today

Today the PREST param files in absolute-seafloor-pressure/PREST-data-collection were brought in sync with the updated set in

coszo-data-collection: pressure channels (UDO/LDO) changed from r_value = 0.0001450377 with PSIA output units to a flat r_value = 1.0 with PA/pascal units  plus a new conversion = 0.0001450377 parameter (1 Pa = 0.0001450377 PSI), which the pipeline now applies during MiniSEED conversion (OOI_data_request_and_convert_mseed.py line 854) instead of encoding it in the StationXML response, and station files gained the loc = 10 key used in XML filenames. 

A new script, bin/make_prest_params.py (modeled on the VEL3D repo's make_vel3d_params.py), was added as the single source of truth that generates all 14 param files from one station/deployment table
Its output was verified to parse key-for-key identical to the hand-maintained COSZO files and to produce byte-identical StationXML. 
The three StationXML files (OO_HYSB1_10, OO_HYS14_10, OO_AXBA1_10) were regenerated in both repos, and everything was committed and pushed to coszo-hub/absolute-seafloor-pressure (main) and 7018e09 to mikaut/coszo-data-collection (dev/maleen). 

Known issues left open: temperature channels (UK1/LK1) lack a conversion key, which will KeyError in the live pipeline; 
backfill_mseed_from_nc.py and plot_from_netcdf.py still divide by r_value (now 1.0) so they no longer convert PSI→Pa; and HYS14's LK1 file lists two sensor UIDs against a single epoch.
